# A 股交易智能助手 技术架构设计文档

## 一、技术选型说明

### 1.1 前端技术栈

> 前端：React + TypeScript + Ant Design 5，PC 网页端，高密度金融信息展示

- **核心框架**：React 18 + TypeScript 5
- **UI 组件库**：Ant Design 5
- **状态管理**：Zustand（管理 AI 会话、自选股、全局 MCP 上下文）
- **图表引擎**：ECharts 5（K 线、财报、资金流向可视化）
- **路由 & 构建**：React Router 6 + Vite
- **HTTP 客户端**：Axios（请求拦截、全局上下文透传）

### 1.2 后端技术栈两套方案

> 同时考虑：RAG、工具调用、Agent，预留后续量化策略 & 回测扩展能力

#### 方案 A：Python + LangChain / LangGraph【推荐】

> 优势：AI 生态成熟，量化回测工具链原生丰富，迭代快

- Web 框架：FastAPI（异步高性能，适配大模型推理）
- AI 智能体：LangChain 0.3 + LangGraph 0.2
- 向量数据库：Milvus（RAG 向量检索）
- 业务数据库：MySQL 8.0
- 缓存 / 会话存储：Redis 7
- 时序数据：InfluxDB 2.0（行情、资金时序数据）
- 量化生态：pandas /numpy/backtrader（为后续回测预留）

#### 方案 B：Java + Spring Boot + Langchain4j / Langgraph4j【备选】

> 适合团队以 Java 为主，AI 能力通过 langchain4j 实现，量化模块通过 RPC 调用 Python 量化服务

- Web 框架：Spring Boot 3.2 + Spring Cloud Alibaba
- AI 智能体：Langchain4j + Langgraph4j
- 向量数据库：Milvus
- 存储：MySQL 8.0 + Redis 7 + InfluxDB 2.0
- 量化扩展：对外 RPC 调用 Python 量化回测服务

## 三、各层详细设计

### 3.1 前端应用层

模块化组件架构，对齐 UX 设计规范

- **页面模块**：市场首页、个股详情页、AI 问答页、自选股管理页
- **公共 AI 组件**：AI 解读卡片、对话气泡、风险标签、AI 思考加载组件
- **公共业务组件**：K 线组件、财报指标卡片、板块榜单、新闻列表组件
- **全局状态**：登录态、自选股列表、AI 会话状态
- **交互约束**：AI 输出统一格式，自动追加合规声明；

### 3.2 API 网关层

- 核心能力：请求路由、身份鉴权、参数校验、限流熔断、全链路日志
- MVP：FastAPI 路由 / Spring Cloud Gateway；后期可独立网关集群

### 3.3 业务服务层

按业务域拆分，只做业务编排，不耦合大模型推理细节

1. **市场热点服务**：编排市场复盘 Agent，输出首页速览、新闻解读、板块榜单、宏观数据
2. **个股分析服务**：调用行情 / 财报工具 + RAG 引擎，输出走势、财报、综合评分
3. **智能问答服务**：调度问答 Agent，多轮对话、自动工具调用、合规拦截
4. **自选股服务**：管理自选股，触发风险扫描 Agent，输出风险标签
5. **用户服务**：账号、偏好、浏览记录
6. **【预留】量化策略回测服务**：后续扩展，策略回测、绩效分析、因子验证

### 3.4 基础设施层

- 容器化：Docker + K8s，AI 推理节点弹性扩缩容
- 监控：Prometheus + Grafana，监控接口耗时、Agent 成功率、数据延迟
- 日志：ELK，全链路追踪，满足合规审计留存
- 安全：HTTPS、数据脱敏、接口鉴权、异常流量拦截

## 四、AI 智能体引擎层（核心）

> 对应 PRD：RAG、工具调用、MCP 上下文、Agent Loop，基于 LangGraph 实现有状态智能体。

### 4.1 RAG 向量知识库引擎

模块组成：知识库管理模块 + 向量检索引擎 + 重排序模块 + 生成模块

1. **知识库分类**
   - 财报规则库
   - 宏观政策库
   - 市场规律库
   - 技术指标库
   - 合规风控库
2. **存储**：Milvus 存向量，MySQL 存储原文与元数据
3. **检索链路**
   > Agent / 用户请求 → Query 改写 → 向量召回 Top10 → 重排序 → Prompt 注入 → LLM 生成
4. **更新策略**：规则库增量更新；财报季批量更新财报相关规则
5. **目标**：降低大模型幻觉，保证金融专业度、输出合规。

### 4.2 工具调用网关

模块组成：工具注册中心 + 调用调度器 + 数据标准化层
**内置金融工具集**

- 行情查询工具：个股 / 板块实时量价
- 财报数据工具：结构化财报指标、同比环比
- 热点资讯工具：资讯聚合、去重过滤
- 板块资金工具：板块涨幅、主力资金流入流出
- 宏观数据工具：PMI、CPI、北向资金、汇率等

> 调用流程：Agent 选择工具 → 网关调用 → 数据清洗格式化 → 返回 Agent 上下文
> 扩展点：预留注册接口，未来接入因子计算、回测引擎工具。

### 4.3 MCP 上下文管理模块

1. **场景上下文**：访问个股 / 板块生成场景 ID，绑定标的、浏览轨迹
2. **会话记忆**：Redis 存储会话历史、已调用工具、RAG 检索片段
3. **跨页面透传**：网关透传场景 ID；自选股→个股→问答，上下文无缝继承，用户不用重复输入股票代码
4. **预留**：多模态图表特征提取接口，未来支持 K 线 / 表格理解。

### 4.4 Agent 编排引擎（LangGraph）

Agent 标准执行链路：
`任务输入 → 需求拆解 → 工具调用取数 → RAG知识增强 → 推理生成 → 合规校验 → 结果输出`

> 信息不足时自动循环补全。

表格

| Agent 类型             | 触发方式                                     | 对应产品功能                  |
| ---------------------- | -------------------------------------------- | ----------------------------- |
| 市场复盘 Agent         | 定时触发（开盘 / 盘中 / 收盘）+ 用户访问首页 | 首页 AI 市场速览、热点解读    |
| 个股分析 Agent         | 用户进入个股页触发                           | 走势、财报、综合评分          |
| 问答 Agent             | 用户提问触发                                 | AI 智能多轮问答               |
| 风险扫描 Agent         | 定时轮询 / 自选股变更                        | 自选股风险标签                |
| 【预留】策略优化 Agent | 量化模块上线后                               | AI 诊断回测结果、优化策略参数 |

## 五、数据架构设计

### 5.1 数据存储选型

表格

| 数据类型                  | 存储                  | 用途                       | 更新频率   |
| ------------------------- | --------------------- | -------------------------- | ---------- |
| 用户业务数据              | MySQL                 | 用户信息、自选股、浏览记录 | 实时       |
| 实时行情数据              | InfluxDB + Redis      | 价格、成交量、资金流向     | 秒级       |

- 数据清洗：格式化、去重、异常值校验
- 同步机制：实时数据 Kafka 异步同步；离线数据定时批量同步

## 六、核心业务流程示例

### 6.1 首页市场复盘流程

1. 用户访问首页，网关转发请求到市场热点服务
2. 市场热点服务调用**市场复盘 Agent**
3. Agent 通过工具网关拉取新闻、板块资金、宏观数据
4. Agent 调用 RAG 检索知识库，做逻辑推理
5. 生成复盘结果，经过合规校验
6. 结构化返回前端渲染 AI 速览卡片、新闻、板块榜单

### 6.2 AI 多轮问答流程

1. 用户输入问题，请求携带 MCP 会话 ID 进入问答服务
2. **问答 Agent**加载会话上下文，识别用户意图与当前标的场景
3. 判断是否需要调用工具获取实时数据
4. 检索 RAG 知识库（专业规则 + 合规）
5. LLM 生成回答，合规校验拦截违规输出
6. 更新 Redis 会话上下文，返回前端渲染；后续对话自动继承上下文。

## 七、量化策略 & 回测扩展设计

> 不改动现有核心架构，新增模块平滑扩展。

### 7.1 扩展层

- 业务服务层新增：**量化策略回测服务**
- AI 引擎层新增：**策略优化 Agent**
- 数据中台新增：因子库、历史回测数据集

### 7.2 核心扩展模块

1. **因子计算引擎**：估值、成长、动量等量化因子计算
2. **回测引擎**：backtrader/zipline，策略回测、滑点手续费模拟、绩效指标
3. **策略管理**：策略创建、参数配置、任务调度、结果存储
4. **策略优化 Agent**：基于回测结果 AI 诊断、参数调优、大白话解读风险

### 7.3 和现有系统复用

- 复用已有行情、财报、宏观数据
- 复用 RAG 做量化指标解读
- 复用 Agent 编排框架
- 前端复用 ECharts 渲染净值、回撤、绩效图表

### 7.4 演进路线

1. 阶段 1：历史行情接入，单因子回测可视化
2. 阶段 2：完整回测引擎，支持多因子策略回测
3. 阶段 3：策略优化 Agent 上线
4. 阶段 4：模拟盘信号提醒

## 八、合规与安全架构

1. **输入拦截**：违规词库拦截荐股、预测涨跌类提问
2. **输出管控**：AI 输出强制追加免责声明；RAG 合规库约束输出边界
3. **数据合规**：公开数据可溯源；用户数据脱敏存储传输
4. **审计留痕**：全链路日志留存≥6 个月，AI 输出可溯源审计
5. **抽检机制**：AI 输出人工抽检，迭代优化 RAG 规则

## 九、MVP 部署架构

- 前端：静态资源 Nginx + CDN
- 后端服务：Docker 容器化部署，MVP 单节点运行
- AI 推理：对接第三方大模型 API；Prompt、私有 RAG 知识库本地部署
- 存储组件：MySQL / Redis / Milvus / InfluxDB MVP 单节点，后续集群扩容
- 监控告警：基础监控 + AI 输出合规抽检

## 十、MVP 技术落地路径

1. **阶段 1：基础能力**：前端页面开发、业务接口、数据源对接、基础工具调用网关
2. **阶段 2：AI 核心能力**：轻量化 RAG 知识库、LangGraph 问答 Agent、合规校验、基础 MCP 上下文
3. **阶段 3：主动智能体**：市场复盘 Agent、自选股风险扫描 Agent，首页 & 自选股 AI 能力落地
4. **阶段 4：联调上线**：全链路联调、合规测试、性能调优、上线验证
